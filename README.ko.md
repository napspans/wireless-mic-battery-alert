# wireless-mic-battery-alert

[日本語](./README.md) · [English](./README.en.md) · [한국어](./README.ko.md) · [简体中文](./README.zh.md) · [Français](./README.fr.md)

무선 마이크의 배터리 방전이나 연결 이상을 수신기의 신호 두절로 감지해 사용자에게 알리는 Windows 애플리케이션입니다.

## 개요

- 무선 마이크 수신기를 감시하다가 송신기 신호가 끊기면 알립니다
- 알림음, 일시정지 사운드, 모니터링 중지·재개 사운드를 설정할 수 있습니다
- 상주 중에도 Windows의 절전 모드 진입을 방해하지 않습니다
- 日本語, English, 한국어, 简体中文, Français를 지원합니다
- Windows용 `.exe` 배포를 전제로 합니다

## 감지 방식

송신기의 전원이 꺼지면 수신기는 **완전한 디지털 무음**(값이 정확히 0인 샘플)을 출력합니다. 반대로 송신기가 살아 있는 한 0 샘플은 나타나지 않습니다. 이 앱은 그 차이를 판정에 사용합니다.

실측값 (BOYA mini / WASAPI 경유 / 각 10초):

| 상태 | 0 샘플 비율 | 0이 아닌 최솟값 |
|---|---|---|
| 송신기 ON | 0.0000% (480,000 샘플 중 0개) | 2.9e-14 |
| 송신기 OFF | 100.00% | 없음 |

음량 수준에 의존하지 않으므로 임계값을 조정할 필요가 없고, 주변이 조용한지 여부에도 좌우되지 않습니다.

### 음량 임계값을 쓰지 않는 이유

Windows 11의 **Voice Clarity**(캡처 경로에 삽입되는 AI 노이즈 억제 APO)가 켜진 환경에서는 배경 소음이 강하게 억제되어, **송신기가 살아 있어도 조용한 방에서는 -100 dB 아래**까지 떨어집니다. "배터리가 없을 때의 잡음"과 "배터리가 있는 상태의 환경음" 사이의 차이가 사라지므로, 임계값을 어디에 두어도 둘을 구분할 수 없습니다. 신호 두절에 의한 판정은 이 영향을 받지 않습니다.

## 절전 모드를 방해하지 않는 구조

마이크를 열어 둔 채로 두면 USB 오디오 드라이버가 Windows에 SYSTEM 전원 요청을 계속 세워 PC가 절전 모드로 들어가지 못합니다. 애플리케이션 쪽에서 이 요청을 철회할 수단은 없으므로, **스트림 자체를 닫는** 수밖에 없습니다.

이 앱은 PC가 계속 유휴 상태이면 모니터링을 자동으로 중지해 스트림을 닫고, 조작이 재개되면 자동으로 다시 엽니다. "PC를 만지지 않는다 = 무선 마이크도 쓰지 않는다"이므로 실용상 잃는 것은 없습니다.

- 자동 중지·자동 재개에서는 알림음을 재생하지 않습니다 (수동 조작과 구분하기 위해)
- 수동으로 모니터링을 중지한 경우에는 조작을 재개해도 자동으로 되살아나지 않습니다
- 다른 앱(Discord, OBS 등)이 마이크를 사용하는 동안에는 모니터링을 계속합니다. 그동안은 그 앱이 전원 요청을 세우므로, 이쪽이 닫아도 절전 모드로 들어가지 않기 때문입니다

유휴로 판정할 시간은 사용 중인 환경의 Windows 절전 설정보다 짧게 지정하세요 (기본값 180초).

절전을 방해하는 요인은 이 앱만이 아닙니다. 동영상을 재생 중인 브라우저나 소리를 내는 다른 앱도 전원 요청을 세웁니다. 절전 모드로 들어가지 않을 때는 관리자 권한으로 `powercfg /requests`를 실행하면 어떤 장치나 프로세스가 요청을 세우고 있는지 확인할 수 있습니다.

## 주요 기능

- 입력 장치 선택 (WASAPI)
- 신호 두절에 의한 배터리 방전 감지
- 알림 간격 설정
- 알림음 변경 (기본 제공 5종 / 임의의 WAV 파일)
- 일시정지 사운드, 모니터링 중지·재개 사운드 설정
- 경고 후 모니터링 자동 일시정지와 신호 복귀 시 자동 재개
- PC 유휴 상태와 연동한 모니터링 자동 중지·재개 (절전 방해 회피)
- 현재 입력 레벨 (dB / 무음률) 실시간 표시
- 작업 표시줄 트레이 상주 (상태를 색으로 나타내는 아이콘, 설정 파일과 로그로 가는 링크)
- 표시 언어 전환 (日本語 / English / 한국어 / 简体中文 / Français)
- 라이트 / 다크 테마 (Windows 설정에 연동)
- Windows용 EXE 빌드

## 작업 표시줄 트레이

상주 중에는 트레이 아이콘이 현재 상태를 색으로 나타냅니다.

![트레이 아이콘](./docs/images/tray-icons.png)

| 아이콘 | 상태 | 의미 |
|---|---|---|
| 회색 | 중지됨 | 수동으로 모니터링을 중지한 상태. 조작을 재개해도 자동으로 되살아나지 않습니다 |
| 초록 | 모니터링 중 | 정상적인 모니터링 상태 |
| 빨강 | 경고 | 신호 두절을 감지해 알린 직후 (5초간) |
| 주황 | 일시정지 | 경고 후의 자동 일시정지. 마이크는 열린 채이며, 신호가 돌아오면 자동 재개합니다 |
| 하늘색 | 자동 중지 | PC 유휴로 마이크를 닫은 상태. 조작을 재개하면 자동으로 돌아옵니다 |

**주황과 하늘색의 차이**가 중요합니다. 주황(일시정지)은 경고를 울리는 것만 멈출 뿐 마이크는 열린 채이고, 하늘색(자동 중지)은 마이크를 닫습니다. 절전을 방해하지 않는 것은 하늘색 상태입니다.

우클릭 메뉴에서 설정 창 열기, 모니터링 시작/중지, 설정 파일 위치 열기, 로그 열기, 종료를 할 수 있습니다.

## 설정 항목

| 항목 | 설명 |
|---|---|
| 입력 장치 | 감시할 무선 마이크 수신기. 장치 번호는 재열거 시 바뀌므로 설정에는 이름을 저장합니다 |
| 알림 간격 (초) | 신호 두절이 이어지는 동안 경고를 반복하는 간격 |
| 전체 음량 | 알림음의 음량 (0~100) |
| 알림음 | 배터리 방전을 감지했을 때 재생하는 소리 |
| 일시정지 사운드 | 자동 일시정지했을 때 재생하는 소리 |
| 모니터링 중지 / 재개 사운드 | 수동으로 모니터링을 전환했을 때 재생하는 소리 |
| 자동 일시정지 | 지정한 횟수만큼 경고한 뒤 모니터링을 일시정지합니다 |
| 일시정지까지의 경고 횟수 | 기본값 1회 |
| 유휴 시 자동 중지 | PC가 계속 유휴 상태이면 모니터링을 중지합니다 (기본값 사용) |
| 유휴로 판정할 시간 (초) | 기본값 180초 (30~1800) |
| 다른 앱 사용 중 계속 | 다른 앱이 마이크를 사용 중이면 모니터링을 계속합니다 (기본값 사용) |
| 테마 | 시스템 설정 / 라이트 / 다크 |
| 언어 | 日本語 / English / 한국어 / 简体中文 / Français |

언어는 선택하는 즉시 화면에 반영됩니다. 다시 시작할 필요가 없습니다. 처음 실행할 때는 Windows 로캘에서 추정하며, 해당하는 번역이 없으면 영어를 사용합니다.

설정은 변경하면 자동 저장됩니다. 화면 아래쪽에 저장 시각과 버전이 표시됩니다.

설정 파일 `config.json`은 실행 파일과 같은 위치에 저장됩니다. 트레이 우클릭 메뉴의 "설정 파일 위치 열기"에서 찾아갈 수 있습니다.

설정한 수신기를 찾을 수 없으면 WASAPI 기본 장치로 자동 전환합니다. 절전에서 복귀하거나 USB를 다시 꽂아 장치 번호가 바뀌어도 모니터링을 이어갈 수 있습니다.

신호 두절과 복귀 판정에는 각각 1초의 여유가 있어, 무선의 순간적인 끊김이나 전원을 켠 직후 링크를 맺는 동안에 잘못 반응하지 않습니다. 이 값은 설정 항목이 아니라 내부 상수입니다.

## 로그

동작 기록을 실행 파일과 같은 위치의 `logs/app.log`에 출력합니다. 트레이 우클릭 메뉴의 "로그 열기"에서 찾아갈 수 있습니다.

기록하는 것은 상태가 바뀌었을 때뿐입니다. 시작과 종료, 모니터링 시작·중지(수동인지 유휴 연동인지의 구분 포함), 입력 장치 해결 결과, 경고, 자동 일시정지와 그 해제, 각종 실패를 남깁니다.

상주 앱이므로 로그가 지나치게 늘지 않도록 다음 세 가지로 억제합니다.

| 대책 | 내용 |
|---|---|
| 크기 상한 | 512KB × 3세대. 합계 1.5MB를 넘지 않습니다 |
| 중복 접기 | 직전과 같은 내용은 버리고 건수만 다음 줄에 덧붙입니다 |
| 기본은 INFO | 순회할 때마다 쓰지는 않습니다 |

상세 로그가 필요하면 `config.json`의 `debug_log`를 `true`로 지정하세요. 순회마다 기록이 늘어나므로 상시 사용은 상정하지 않았습니다.
