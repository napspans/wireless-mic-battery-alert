# Step 32: EXE実行時のリソース/設定パス解決を是正

## 目的

第三者レビューで指摘された `__file__` 依存のパス解決リスクをビルド前に解消する。  
特に設定保存先と builtin 音声アセット参照を、通常実行と PyInstaller 実行の両方で一貫して解決できる状態にする。

## 作業対象ファイル

- `wireless-mic-battery-alert-eng/settings.py`
- `wireless-mic-battery-alert-eng/notifier.py`
- `wireless-mic-battery-alert-eng/main.py`

## 変更仕様

- PyInstaller 実行時と通常 Python 実行時の差を吸収するパス解決方針を導入する
- `settings.py` では `config.json` の保存先が EXE 配置物に対して意図した場所へ安定して決まるようにする
- `notifier.py` では builtin 音声アセット参照が EXE 実行時にも壊れないようにする
- `main.py` では相対パス解決に使う基準ディレクトリを上記方針と整合させる
- 3ファイルで個別実装が分岐し過ぎないよう、保守しやすい構造にする

## インターフェース制約

- 既存の公開インターフェースは維持する
- 設定ファイル名は `config.json` のままとする
- builtin 音声指定形式（`builtin:...`）と custom 指定形式（`custom:...`）は維持する

## 完了条件

- [ ] 通常の Python 実行で既存機能が壊れない
- [ ] PyInstaller 実行を想定したパス解決ロジックが `settings.py` / `notifier.py` / `main.py` で整合している
- [ ] `config.json` 保存先が不定にならない構造になっている
- [ ] builtin 音声アセット参照が EXE 実行時にも成立する構造になっている

## 動作確認手順

1. `python main.py` を起動し、設定変更後に再起動して設定保持を確認する
2. builtin 音声を再生し、エラーなく鳴ることを確認する
3. 主要な相対パス解決が変更後も通常実行で破綻していないことを確認する

## 注意事項

- 今ステップでは依存バージョン固定や最終ビルドは行わない
- EXE実機確認の詳細は後続ステップで行う前提で、今回はビルド前の構造是正に集中する
