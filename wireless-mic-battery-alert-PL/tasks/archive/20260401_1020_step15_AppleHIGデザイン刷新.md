# Step 15: Apple HIG に基づくUIデザイン刷新

## 目的

POのフィードバック：「前身プロジェクトと全く変化がない。Apple デザイン思想が感じられない」

現状の問題：
- `theme.py` に COLORS・FONTS が定義されているが、ほとんどのウィジェットに適用されていない
- 前身プロジェクトも同じ sv_ttk + Meiryo UI を使っており、コードレベルの差異はほぼない
- Apple HIG の核心（明確な視覚的階層・余白・アクセントカラーの適切な使用）が実現されていない

このステップで Apple HIG の精神を実際に画面に反映する。

## 作業対象ファイル
- `wireless-mic-battery-alert-eng/gui.py`
- `wireless-mic-battery-alert-eng/theme.py`

## 変更仕様

### 1. 主要アクションボタンへのアクセントカラー適用

「監視 開始 / 停止」ボタンに sv_ttk が提供する `Accent.TButton` スタイルを適用する。
これにより `COLORS["accent"]`（`#0071e3`）が視覚的に現れ、前身との明確な差異が生まれる。

`_build_button_area()` のボタン生成時に `style="Accent.TButton"` を指定すること。

### 2. カード型レイアウトの導入

各タブのコンテンツ（「デバイスと検知パラメータ」等のセクション）を、
背景色 `COLORS["surface"]` を持つ `tk.Frame`（ttk.Frame ではなく tk.Frame）で囲み、
セクションが「カード」として浮き上がって見えるようにする。

カードの実装要件：
- 背景色: `COLORS[theme]["surface"]`（例: lightテーマで `#ffffff`）
- 内側パディング: 12px 程度
- カード自体のパディング（カードと親フレームの間隔）: 8px 程度
- セクション見出しラベルもカード内に含める

テーマ切り替え時（`_on_save` 内の `apply_theme` 後）にカード背景色も更新すること。

### 3. 視覚的階層の強化

各タブの section 見出し（例:「デバイスと検知パラメータ」）と、
各行のラベル・値の色を明確に分離する：

- セクション見出し: `COLORS[theme]["label"]` + `FONTS["headline"]`（実装済みだが背景との対比が弱い）
- 行ラベル: `COLORS[theme]["label"]` + `FONTS["body"]`
- セカンダリ情報がある場合: `COLORS[theme]["secondary_label"]`

`ttk.Label` はデフォルトで foreground を継承するが、
明示的に `foreground=colors["label"]` を指定することで、テーマ変更後も色が追従するようにする。

### 4. ウィンドウ背景色の確実な適用

現状、`root.configure(background=...)` は設定しているが、
`ttk.Frame` がその上を覆うため bg color が見えていない可能性がある。

トップレベルの Frame（waveform_frame 等）に `style` を使うか、
または tk.Frame として `background=colors["bg"]` を明示指定して、
ウィンドウ全体に `#f5f5f7`（lightテーマ）が見えるようにする。

## インターフェース制約

`apply_theme(root, theme)` のシグネチャは変更しない。
テーマ切り替えで背景やカード色を更新するために、
`SettingsGUI` 内でカード Frame への参照を保持し `_on_save` から更新できるようにすること。

## 完了条件
- [ ] 「監視 開始/停止」ボタンがアクセントカラー（青）で表示される
- [ ] 設定フォームのセクションがカード状（白背景）で視覚的に分離されている
- [ ] ウィンドウ全体の背景色がライトグレー（`#f5f5f7`）として見える
- [ ] lightテーマ・darkテーマ切り替え時にカード背景色も追従する
- [ ] 既存の設定保存・監視トグル等の動作が維持されている

## 注意事項
- sv_ttk の `Accent.TButton` は sv_ttk 標準スタイルであり、独自カラー定義は不要
- tk.Frame を使う場合は `highlightthickness=0` を指定してデフォルトの境界線を消すこと
- 過度な装飾（影・グラデーション・枠線の多用）は Apple HIG に反する。シンプルさを保つこと
- コードの複雑さが増す場合は、カード参照リストを `self._cards` として管理する方法を推奨する
