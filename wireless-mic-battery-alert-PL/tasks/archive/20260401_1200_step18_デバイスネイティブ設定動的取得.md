# Step 18: monitor.py — デバイスのネイティブ設定動的取得

## 目的

ストリーム起動時にデバイスのサンプルレートとチャンネル数をハードコード値から取得するのではなく、
`sd.query_devices()` でデバイスのネイティブ設定を動的取得して使用する。

現状、`_SAMPLERATE = 44100` / `_CHANNELS = 1` を固定使用しているため、
48000Hz専用のUSBデバイスやステレオ専用デバイスで `PortAudioError` が発生してアプリが起動できない。

## 作業対象ファイル

- `wireless-mic-battery-alert-eng/monitor.py`

## 変更仕様

`AudioMonitor.start()` メソッドの `sd.InputStream(...)` 呼び出し前に、対象デバイスの情報を取得する処理を追加する。

- `sd.query_devices(device, kind="input")` でデバイス情報を取得する
- `default_samplerate` を `int` キャストしてサンプルレートとして使用する
- `max_input_channels` を取得し、1以上2以下に収めてチャンネル数として使用する
- 波形バッファ（`_waveform_buf`）をこのサンプルレートを元に1秒分のサイズで再初期化する
- `sd.InputStream` にはこれらの動的取得値を渡す（クラス変数 `_SAMPLERATE` / `_CHANNELS` は渡さない）

クラス変数 `_SAMPLERATE`、`_CHANNELS`、`_BUFFER_SIZE` は `__init__` での初期化用として残してよいが、
`start()` 内では動的取得値で上書きすること。

`_audio_callback` 内の `indata[:, 0]`（ch0のみ使用）はチャンネル数が1以上保証されるため変更不要。

## インターフェース制約

なし（内部実装のみの変更）

## 完了条件

- [ ] `start()` 内で `sd.query_devices()` を呼んでデバイスのサンプルレートとチャンネル数を取得している
- [ ] `sd.InputStream` にはハードコードの `_SAMPLERATE` / `_CHANNELS` ではなく動的取得値が渡されている
- [ ] `_waveform_buf` がそのサンプルレートをもとに1秒分のサイズで再初期化されている
- [ ] `_audio_callback` の `indata[:, 0]` は変更されていない

## 注意事項

- `device` が `None`（既定デバイス）の場合も `sd.query_devices(None, kind="input")` で動作する
- チャンネル数の下限は1（`max(1, ...)` 等で保証）、上限は2（超多チャンネルデバイス対策）
