# Step 16: 入力デバイス WASAPI絞り込み

## 目的

設定画面の「入力デバイス」ドロップダウンに、Windowsサウンド設定の「録音」タブに存在しない仮想デバイスや重複エントリが大量表示される問題を修正する。

PortAudio は WASAPI・DirectSound・MME など複数ホストAPI経由で同一物理デバイスを重複列挙する。Windowsサウンド設定「録音」タブと同等の表示にするため、WASAPIのみに絞り込む。

## 作業対象ファイル

- `wireless-mic-battery-alert-eng/monitor.py`

## 変更仕様

`list_input_devices()` の実装を以下の方針で変更する。

1. `sd.query_hostapis()` でホストAPI一覧を取得し、名前に "WASAPI" を含むAPIのインデックスを特定する
2. WASAPIが見つかった場合は、そのホストAPIに属する入力デバイスのみを返す
3. WASAPIが見つからない場合（macOS・Linux等）は、従来通り全入力デバイスを返す（フォールバック）

既存の `is_default` フラグ付与・「（既定）」表示ロジックはそのまま維持すること。

## インターフェース制約

関数シグネチャは変更しない:
```
def list_input_devices() -> list[dict]
```

戻り値の dict 構造も変更しない:
```
{"index": int, "name": str, "is_default": bool}
```

## 完了条件

- [ ] Windows環境で `list_input_devices()` を呼び出したとき、返るデバイス数がWindowsサウンド設定「録音」タブの表示件数と一致する
- [ ] WASAPI以外のホストAPI（DirectSound・MME等）経由のデバイスが含まれない
- [ ] 既定デバイスに「（既定）」が付く動作が引き続き機能する
- [ ] WASAPIが存在しない環境向けのフォールバック処理が実装されている

## 注意事項

- `test-code/` ディレクトリにホストAPIごとのデバイス確認スクリプトを作成し、修正前後の出力を比較すること
- 内部実装（ループ構造・変数名等）はEngに委ねる
