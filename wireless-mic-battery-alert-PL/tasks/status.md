PO 報告の UI 不具合3件（プルダウン内のフォント／チェックボックスの背景色／
シークバーの背景色）は、いずれも **独自パレットと sv_ttk のパレットが二重に
存在していたこと** が原因だった。sv_ttk は画像スプライトのテーマで、背景色が
PNG に焼き込まれているため、`ttk.Style` での色指定では直らない。地の色を
sv_ttk と同値にし、カードの区切りをボーダーに変えることで解消した。

あわせて UI 全体を ja / en / ko / zh / fr の5言語に対応させた。

自動テストは7ファイル・検証項目 174 件がパス（うち `test_i18n.py` が 70 件）。

実装中に判明した事項:

- **名前付きフォントは黙って消える。** `tkinter.font.Font` は `__del__` で
  `font delete` を呼ぶため、生成して参照を捨てると名前付きフォントごと消え、
  Tk の既定フォント（ＭＳ Ｐゴシック）に戻る。参照を保持する方式では、2回目に
  `nametofont()` の戻り値で置き換えた時点で生成元が回収され再発したため、
  `delete_font` を False にして削除自体を止めている
- **`option_add` はウィジェット生成時にしか読まれない。** 従来 `apply_theme()`
  の中で呼んでいたが、`_build_settings_form()` の後だったため一切効いていなかった。
  生成前の `init_options()` と、生成後に実体を叩く `style_popdown()` に分けた
- Combobox の値が日本語文字列そのもので dict のキーも兼ねていたため、言語を
  変えると設定の読み書きが壊れる構造だった。`_KeyedCombo` でキーと表示を分離した
- **入力系ウィジェットにはスタイルのフォントが届かない。** `ttk` の Combobox /
  Entry / Spinbox は自前の `-font` を持ち、ウィジェット側の指定はスタイルより
  強い。さらに sv_ttk の `config_entry_font`（sv.tcl:22）が生成時に
  `-font SunValleyBodyFont` を書き込むため、結果は「ウィジェット生成」と
  「テーマ適用」の順序で変わる。どちらの経路でも実体（`Segoe UI Variable Text`
  または `TkTextFont`）は CJK を十分に持たず既定フォントへ落ちる。テーマ適用後に
  `theme.apply_widget_fonts()` で明示的に上書きしている
- **`ttk.Checkbutton` はスタイル経由なら折り返せる。** ウィジェットには
  `-wraplength` が無いが、ラベル要素はスタイルの指定を受け付ける。翻訳が長い
  言語のためにウィンドウを広げると日本語が間延びするため、この方法で幅 640 を
  保ったまま解決した
