# 全体設計

## プロジェクト目標

ワイヤレスマイクの受信機からの信号途絶を監視し、電池切れや接続異常をユーザーへ通知する Windows デスクトップアプリケーションを提供する。  
成功条件は、常駐監視・通知・設定保存・EXE配布が実用レベルで安定動作すること。

## アーキテクチャ概要

- `main.py`: アプリ全体の起動、設定読込、監視制御、通知連携、GUI/トレイ連携。通知音は単一のワーカーで直列再生する
- `monitor.py`: 入力デバイス監視、信号途絶判定、状態遷移コールバック
- `notifier.py`: builtin/custom 音声の解決と再生
- `settings.py`: 設定ファイルの読込・保存
- `gui.py`: 設定画面とユーザー操作
- `tray.py`: タスクトレイ常駐とメニュー操作
- `build.spec`: PyInstaller による EXE 化設定

依存方向は、UI/トレイ/通知/監視が `main.py` に集約され、各下位モジュール同士は直接結合しない。

## 技術的制約

- 言語: Python
- 実行環境: Windows
- GUI: tkinter / ttk / sv_ttk
- 音声再生: pygame
- 音声入力監視: sounddevice, numpy
- 配布形式: PyInstaller による `.exe`（onedir 想定）

## 検出方式

送信機の電源が切れると受信機は完全なデジタル無音（厳密に 0 のサンプル）を出力し、送信機が生きている間はゼロサンプルが現れない。この差をブロック単位のゼロサンプル率で判定する。

音量しきい値による判定は採用しない。Windows 11 の Voice Clarity のようなノイズ抑制 APO が有効な環境では、送信機が生きていても静かな場所では -100 dB 以下まで落ち、電池切れ状態と区別できなくなるため。

入力デバイスは WASAPI のものを明示的に選ぶ。MME / DirectSound 経路は 16bit の ±1LSB ディザが乗り、信号途絶時でも完全なゼロにならないため判定が成立しない。

## 設計方針

- モジュール責務を明確に分離し、設定・通知・監視・UI の境界を保つ
- 判定に使う値は、環境やユーザー設定に依存しない物理的な差に基づかせる
- ユーザーが調整しなくてよいパラメータは設定項目にせず内部定数とする
- 実行環境差分（スクリプト実行 / PyInstaller 実行）は共通の解決方針を持たせる
- UI変更は既存の視覚言語を崩さず、動作変更と混在させない
- ビルド再現性に関わる情報はコード変更とは別に記録し、追跡可能にする

## テスト方針

- 単体レベル: 設定読込保存、パス解決、例外系の破綻がないことを確認する
- 統合レベル: 監視開始停止、通知音再生、GUI保存、トレイ連携を確認する
- 受け入れレベル: EXE 起動、設定永続化、builtin 音再生、エラー表示を確認する
- 手動確認を中心とし、ビルド前後で再現手順を明文化する
- 検出方式に関わる変更は、実機の送信機ON/OFF双方を実測して裏付けを取る
