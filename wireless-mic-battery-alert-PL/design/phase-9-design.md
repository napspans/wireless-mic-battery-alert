# Phase 9: 検出方式の刷新と設定項目の整理

## 目的

音量しきい値による無音判定が実環境で成立しなくなったため、検出方式を信号途絶の検知に置き換える。あわせて、しきい値方式を前提としていた設定項目を整理する。

## 背景

運用中に「電池切れを検知できない」事象が発生した。当初はマイクのファームウェア更新が疑われたが、実測により原因は Windows 側にあることが判明した。

### 実測で確認した事実

1. キャプチャエンドポイントに `VocaEffectPack`（Microsoft の **Voice Clarity**、AI ノイズ抑制の APO）が挿入されていた
2. その影響で、送信機が生きていても静かな場所では **-100 〜 -148 dB** まで落ちる。電池切れ時のノイズとの差が消え、しきい値を置く余地がない
3. 一方、送信機の電源を切ると受信機は **100% 完全なデジタル無音**（厳密に 0 のサンプル）を出力する
4. 送信機が生きている間、ゼロサンプルは **480,000 サンプル中 1 個も出ない**

| 状態 | ゼロサンプル率 | 非ゼロの最小値 |
|---|---|---|
| 送信機ON | 0.0000% | 2.9e-14 |
| 送信機OFF | 100.00% | なし |

### 併発していた不具合

- `device_index` 未設定時に PortAudio の既定デバイス（MME）へ落ちていた。GUI は WASAPI のデバイスのみを一覧表示するため、画面の表示と実際の監視対象が食い違っていた
- MME / DirectSound 経路では信号途絶時も 16bit の ±1LSB ディザ（3.052e-05）が乗り、ゼロ率が 40〜62% にとどまる。判定が成立しない
- 既定デバイスの判定を、MME 側のインデックスと WASAPI 側のインデックスで比較していたため、常に不一致だった

## 主な決定事項

**判定はゼロサンプル率のみで行う。** しきい値方式は選択肢としても残さない。実測で誤検知することが確認されているため、選べること自体が誤設定を招く。

**猶予は設定項目にしない。** 信号途絶・復帰ともに 1 秒の確認時間を持たせるが、ユーザーが調整する意味がないため内部定数（`_SIGNAL_LOST_SEC` / `_SIGNAL_BACK_SEC`）とする。復帰側の猶予は、電源投入直後のリンク確立中に復帰と途絶を往復して通知音が乱発する問題への対処。

**通知音は単一ワーカーで直列再生する。** 従来は再生ごとにスレッドを起こしていたため、状態が続けて変わると複数の音が重なった。キューは上限付きとし、短時間に状態が何度も変わっても滞留させない。

**スタートアップ起動の設定は削除する。** チェックボックスと設定値は存在したが、レジストリ登録もショートカット作成も実装されておらず、有効にしても何も起きなかった。Step 36 の受け入れ確認で唯一スキップされた項目であり、発覚が遅れた。

## 削除した設定項目

| 項目 | 理由 |
|---|---|
| 無音閾値 (dB) | 検出方式の変更により未使用 |
| 無音継続時間 (秒) | 内部定数（1秒）に置き換え |
| 検出方式 | 選択肢を持たせない方針のため |
| スヌーズ解除秒数 | 復帰判定が内部定数になったため |
| スタートアップ起動 | 未実装の設定だったため |

`auto_snooze_*` は `auto_pause_*` に改称した。既存の `config.json` は読み込み時に自動で移行する。

## テスト計画

- 検出判定: 発話 / 無言 / MME経路のディザ / 完全なゼロ の 4 パターンを区別できること
- 一時停止フロー: 途絶→アラート→一時停止→復帰→再途絶の順序が正しいこと
- ばらつき耐性: 0.3 秒間隔で信号が途切れる状況で復帰が暴発しないこと
- 通知音: 同時再生数が 1 を超えないこと、設定した音が使われること
- 設定保存: 打鍵のみで変更を検知すること、連続入力でも保存が1回に収まること、保存表示が毎回更新されること
- 設定移行: 旧キーが引き継がれ、廃止キーが `config.json` に残らないこと
