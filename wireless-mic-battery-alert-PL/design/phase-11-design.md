# Phase 11: UI 刷新と多言語対応

## 目的

PO から報告された UI の3つの不具合（プルダウン内のフォント／チェックボックスの背景色／
シークバーの背景色）を、個別の色指定ではなく **原因である二重パレットの解消** によって
根本的に直す。あわせて UI 全体を英語・韓国語・中国語（簡体）・フランス語に対応させる。

## 原因分析

### 1. チェックボックス・シークバーの背景色

`sv_ttk`（Sun Valley テーマ）は **画像スプライトベース** のテーマで、チェックボックスの
インジケータやスライダーのトラフは `spritesheet_{dark,light}.png` に焼き込まれている。
スプライトは sv_ttk 自身の背景色を前提に描かれている：

| | sv_ttk `-bg` | 本アプリ `surface`（カード） |
|---|---|---|
| dark | `#1c1c1c` | `#2c2c2e` |
| light | `#fafafa` | `#ffffff` |

カードは `tk.Frame(background=colors["surface"])` で独自に塗られているため、スプライトの
焼き込み背景と実際の背景が一致せず、矩形の縁が見える。`ttk.Style` で色を指定しても
画像要素なので効かない。**二重パレットが原因**であり、これが「一掃してモダンに」という
要望の実体。

### 2. プルダウン内のフォント

`theme.apply_theme()` の `option_add("*TCombobox*Listbox.font", ...)` には2つの問題がある：

- `option_add` はウィジェット生成**時**にしか参照されない。`apply_theme()` は
  `_build_settings_form()` の**後**に呼ばれるため、既存の Combobox には効かない
- ポップダウンは ttk ではなく素の Tk Listbox のため、背景色・前景色・選択色が未設定のまま
  残り、テーマと無関係な既定色で描画される
- フォント指定がタプル `("Meiryo UI", 10)` で渡されており、option DB の文字列変換に依存する

## 方針

### UI: sv_ttk に一本化する

独自パレットを廃止し、**カードの背景を sv_ttk の `-bg` と完全に一致させる**。カードの
見分けは塗り分けではなく「ページ背景を一段落とす＋1px ボーダー」で付ける。これにより
全ての ttk ウィジェットが自身の想定通りの背景の上に載り、スプライトが馴染む。

| トークン | dark | light | 用途 |
|---|---|---|---|
| `bg`（ページ） | `#141414` | `#f0f0f0` | ルート・タブ地・キャンバス |
| `surface`（カード） | `#1c1c1c` | `#fafafa` | カード内部＝sv_ttk `-bg` と同値 |
| `border` | `#2f2f2f` | `#e2e2e2` | カード枠線・セパレータ |

フォントは **名前付きフォント**（`AppTitle` / `AppHeadline` / `AppBody` / `AppCaption`）に
統一する。名前で参照するため、言語切替時にフォントファミリを差し替えるだけで全ウィジェットに
波及し、option DB へも名前1語で渡せる（タプル変換の問題が消える）。

Combobox のポップダウンは `ttk::combobox::PopdownWindow` を直接引いて `configure` する。
生成後でも確実に効き、テーマ切替にも追随できる。

### i18n: 表示文字列のみ、ログは対象外

- 対象: GUI 全体・トレイメニュー・エラーダイアログ・ファイル選択ダイアログ
- 対象外: `logger` に渡すメッセージ（診断用。ログファイルは日本語のまま）
- 言語は5つ（`ja` / `en` / `ko` / `zh` / `fr`）。初回起動時は OS のロケールから推定する
- 言語別フォント（ja: Yu Gothic UI / en・fr: Segoe UI / ko: Malgun Gothic / zh: Microsoft YaHei UI）

**Combobox の値が日本語文字列そのものだった問題**（`"内蔵: Chime"` が dict のキー兼
表示文字列）を解消する。内部は安定キー（`builtin:chime` 等）で持ち、表示だけを翻訳する
`_KeyedCombo` を導入する。

言語切替は**再起動なしでその場で反映**する。ウィジェット生成時に再翻訳クロージャを登録し、
切替時に全て呼び直す。

## スコープ

対象ファイル:
- `i18n.py`（新規）— 翻訳カタログと `t()`
- `theme.py` — パレット統一・名前付きフォント・ポップダウン設定
- `gui.py` — 文字列の i18n 化・`_KeyedCombo` 導入・カード枠線・言語選択 UI
- `main.py` / `tray.py` / `monitor.py` — 表示文字列の i18n 化
- `settings.py` — `language` 設定の追加
- `test_i18n.py`（新規）/ 既存テスト — カタログ整合とビルド確認
- `README.md` ほか5言語

スコープ外:
- 監視ロジック・音声処理・スリープ連動の挙動変更
- ログメッセージの翻訳
- 通知音設定4系統の統合（PO 判断により現状維持）

## テスト計画

### 自動
- 既存テスト69件が引き続きパスすること
- `test_i18n.py`: 全言語のカタログが `ja` と同一のキー集合を持つこと。`t()` が未知キーで
  例外を出さないこと。ロケール推定が未知ロケールで `en` に落ちること
- `test_gui_build.py`: 5言語それぞれで GUI が例外なく構築できること

### 手動（PO 実施）
1. ライト／ダーク両方で、チェックボックスの周囲とスライダーのトラフに**矩形の縁が
   見えない**こと
2. 通知音プルダウンを開き、リスト内のフォントと背景色が本体と揃っていること
3. 言語を英・韓・中・仏に切り替え、**再起動せずに** 全タブ・トレイメニューが切り替わること
4. 韓国語・中国語で文字化け（豆腐）が出ないこと
5. 言語を変えて再起動しても選択が保持されること

### 合格基準
上記の手動確認1〜5が全て成立し、自動テストが全件パスすること。
